# Pilot Plan

SafeFlow should move in small steps. The point is to learn whether the workflow is worth piloting before anyone talks about live use.

## Phases

| Phase | Goal | Activity | Output | Exit signal |
| --- | --- | --- | --- | --- |
| Phase 0 | Simulation and workflow validation | Review fictional cases, prompt wording and boundary language | Refined workflow and claims notes | The concept is understandable and bounded |
| Phase 1 | Prototype review with clinical staff | Watch the prototype with ward staff and gather feedback | Review notes and backlog items | Staff can explain what the workflow is for |
| Phase 2 | Supervised non-live pilot | Run a shadow-mode style test with no impact on care decisions | Pilot observations and measurement notes | Governance and users are comfortable with next-step learning |
| Phase 3 | Governance-led live implementation only if approved | Complete the required NHS approval path before any live use | Formal implementation plan | Approval is documented before any live deployment |

## Candidate measures

- Escalation visibility
- Handover completeness
- Documentation quality
- Confidence using the escalation workflow
- Safety learning capture
- Usability feedback

## Notes

- Keep the pilot private and controlled until the governance route is agreed.
- Use fictional or simulated scenarios until real data handling is explicitly approved.
- Do not frame the pilot as proof of benefit; frame it as learning.
