# SafeFlow — Evaluation Readiness Summary (SF-210)

Status: simulation-only prototype. The first evaluation session produces **usability and usefulness** evidence only — not clinical evidence. Participants (nurses / nursing students) consent for themselves; no real patient data is involved.

`master-narrative.md` is the controlled wording source.

## Purpose

Confirm that everything needed to run SafeFlow's first simulation evaluation session now exists, and point to each piece. SF-210 (the evaluation framework) is therefore **ready to run** — it now needs scheduling and participants, not more design.

## The evaluation kit (all in place)

| Piece | Document | What it provides |
|---|---|---|
| Framework | `evaluation-framework.md` (SF-220) | Measures, anonymous pre/post forms, SUS, data handling, pre-registered thresholds. **This is the master instrument — if any companion document differs, the framework wins.** |
| Run plan | `build-readiness/first-evaluation-session-plan.md` (SF-223) | Session objective, structure, boundary, 3–6 participants. |
| Facilitator script | `build-readiness/evaluation-session-facilitation-script.md` (SF-235) | Minute-by-minute read-aloud runbook, consent, task sequence, debrief. |
| Capture sheet | `build-readiness/evaluation-feedback-capture-sheet.md` (SF-230) | In-session per-task feedback capture (subordinate to the framework). |
| What they'll use | The live demo (`live-site-demo-walkthrough.md`) + the Ward Quality & Safety Review export | The actual thing participants react to, now publicly reachable. |

## The session in one line

3–6 nurses/students, ~60 minutes: read review cues → generate the Ward Quality & Safety Review export → complete a Competency Passport learning module → anonymous pre/post + SUS + debrief.

## Readiness checklist

- [x] Instrument defined with pre-registered thresholds (SF-220).
- [x] Run plan, facilitator script, and capture sheet written and cross-referenced.
- [x] A working, reachable demo to evaluate (live static build).
- [x] Consent scoped to participants only; simulated data only; no identifiable patient data.
- [ ] **Schedule a date and recruit 3–6 participants.** (The only remaining step — an operational one, not a design one.)
- [ ] Run the session; collect anonymous results against the SF-220 thresholds.
- [ ] Write up findings (usability/usefulness only) and feed into the roadmap.

## Boundary

Usability/usefulness evidence only. Not a clinical trial, not clinical validation. No real patient data. Human review remains central throughout.

## Status

SF-210 is **ready to run**: the framework and all supporting materials are complete and consistent. The next action is scheduling, not further design.
