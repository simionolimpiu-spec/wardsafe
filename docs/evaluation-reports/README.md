# SafeFlow evaluation reports

One report per evaluation session. Reports go here, named `YYYY-MM-DD-session-N.md`, using
`session-report-template.md` in this folder.

`docs/public-demo-pack/evaluation-framework.md` (SF-220) is the master instrument. If this folder
or any template disagrees with the framework, **the framework wins** - do not quietly reword a
measure or a threshold to fit a result.

## Boundary - read before writing a report

These reports produce **usability and usefulness evidence only**. They are not clinical evidence,
not clinical validation, and not a trial. Participants consent for themselves. No real patient data
is involved at any point; every scenario is fictional.

Write-ups must not:

- claim any clinical outcome, patient-safety improvement, or reduction in real deterioration;
- generalise beyond the simulated scenarios that were actually run;
- name or score an individual participant, or compare participants to each other;
- restate a pre-registered threshold in looser terms after seeing the data.

## The thresholds are pre-registered

Set in the framework before any session, precisely so results cannot be adjusted afterwards:

- **SUS 68 or above** (the published average) = "usable"; **80 or above** = strong.
- **M1 improvement of 20% or more** on the SBAR checklist score = a meaningful
  handover-completeness signal.
- **Any single safety-concern response (form Q9)** = a mandatory hazard-log entry before the next
  session is run. This one is a stop condition, not a note.

Report the number against the threshold, including when it misses. A session that comes in under
threshold and says so is more useful to this project than one that reads well.

## Anonymity

Participants are identified only by code (N1, N2, and so on). Codes are assigned in-session and are
not mapped back to names in any file stored in this repo. Free-text quotes must be checked for
self-identifying detail before they are pasted into a report.
