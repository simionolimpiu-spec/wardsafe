# Simulated Trend Model Card

**Version:** `simulation-risk-ml-v0-2-sim`

## Purpose

This model is a simulation-only, educational trend signal for fictional patient journeys. It exists to support structured review, auditability, handover completeness review, escalation readiness cues, discharge-readiness review, and documentation quality exploration.

It does not classify clinical conditions.
It does not propose medicines, doses, or care instructions.
It is not connected to live clinical systems.
Human review is required for every output.

## Training Data

- 100% synthetic data
- 1,500 procedurally generated rows
- 1,200 train rows, 300 synthetic holdout rows
- Generated by `ml/generateSyntheticDataset.js`
- Seeded with `20260703` for reproducible simulation artifacts

Features:

- `news2Normalized`
- `potassiumFallingFlag`
- `documentationQualityNorm`
- `handoverCompleteNorm`
- `openTaskLoadNorm`
- `escalationStateNorm`
- `dischargeBlockerNorm`
- `news2TrendDeltaNorm`
- `safetyFlagLevelNorm`
- `simulationFlagCountNorm`
- `heuristicCueCountNorm`
- `blockerCueCountNorm`
- `documentationCuePresentFlag`
- `handoverCuePresentFlag`
- `escalationCuePresentFlag`
- `dischargeCuePresentFlag`
- `deterioratingObsCuePresentFlag`

Label generation:

- a fixed weighted sum of the synthetic features
- a small deterministic noise term
- a threshold that produces a fabricated 0/1 illustrative deterioration-review flag

The generating formula is documented in the generator script and in the raw synthetic dataset artifact at `ml/data/syntheticTrainingData.json`.

## Intended Use

- simulation-only prototype
- education and demo work
- human-review support for fictional scenarios
- inspectable, deterministic, reviewable model behaviour

## Out of Scope

- real patients
- live clinical use
- condition labelling
- medicines, doses, or care instructions
- automated workflow action
- any claim of real-world clinical performance

## Performance

The toy metrics below are from the synthetic holdout split only. They are illustrative synthetic benchmark numbers, not real-world or clinical performance.

- accuracy: `0.96`
- precision: `0.974`
- recall: `0.974`

These numbers only describe the fabricated synthetic benchmark. They must stay in the data layer and model documentation, not in the Hospital insights UI.

## Retraining

To regenerate the synthetic dataset and refit the model:

1. `npm run ml:generate-dataset`
2. `npm run ml:train`

The checked-in model artifact is written to `src/data/patientJourneyTrendModel.json`.

## Review Notes

- `riskTier` uses simulation-only thresholds:
  - `watch` below `0.4`
  - `review` from `0.4` to `0.7`
  - `urgent` above `0.7`
- `clinical judgement remains central`
- `simulationOnly` is always `true`
- `requiresHumanReview` is always `true`
- `scoreSimulatedTrend()` remains backward compatible with a single feature snapshot and also accepts an array of feature snapshots, using the latest snapshot with derived observation-trend context.
- Hospital insights must keep showing `Illustrative model output, not clinically validated` wherever the simulated trend score is displayed.
